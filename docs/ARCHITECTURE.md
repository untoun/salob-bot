# Архитектура

## Принципы

- **Источник истины — PostgreSQL.** Google Таблица — рабочее окно администратора, а не хранилище.
- **Serverless без состояния в памяти.** Нет `listen()`, `setInterval`, `setTimeout` для критичных задач, in-memory сессий. Всё, что должно пережить вызов функции, лежит в БД.
- **Идемпотентность везде, где возможен повтор:** вебхук (`WebhookEvent.eventId`), создание записи (`Booking.idempotencyKey`), отмена (условный `updateMany`), уведомления (`@@unique(bookingId, type)` и атомарный захват), синхронизация (`SyncQueue`).
- **Время:** в БД UTC, интерфейс и расчёты — `Asia/Yekaterinburg` (Luxon). Слоты считаются в минутах от локальной полуночи.

## Запись без двойного бронирования

1. Слоты клиенту показываются по графику, перерывам, исключениям и уже занятым записям (`lib/booking/slots.ts`).
2. При подтверждении открывается транзакция, берётся `pg_advisory_xact_lock(hashtext(masterId))` — записи одного мастера идут по очереди.
3. Под замком слоты пересчитываются заново; если выбранного времени нет — `SlotTakenError`, клиент видит «время только что заняли» и новые слоты.
4. Запись создаётся с `slotKey = мастер|время`, уникальным в БД; при отмене/переносе `slotKey = NULL` освобождает слот.
5. Для «Любой мастер» перебираются мастера начиная с наименее загруженного за день.

## Синхронизация с Google Таблицей

`SyncQueue` → cron → `runGoogleSync`: аренда (`lease`) исключает параллельные запуски; для каждого листа сначала принимаются правки администратора
(хеш редактируемых полей в скрытой колонке `_hash`; строки, ожидающие записи из БД, не трогаются — БД главнее), затем в таблицу пишутся изменённые и недостающие
сущности. Ошибки → повтор с нарастающей паузой, после 8 неудач `SYNC_ERROR` и уведомление администратору (не чаще раза в час). Сверка недостающих строк и обновление
листов «Расписание/Акции/Настройки/Статистика» — раз в 30 минут.

## Отличия от исходного ТЗ (осознанные)

- **Redis/BullMQ и Express/Dockerfile не используются:** раздел ТЗ про Vercel запрещает постоянные процессы. Очереди — таблицы PostgreSQL + Vercel Cron. `docker-compose.yml` нужен только для локальной БД.
- Записи подтверждаются автоматически; кнопка «Подтвердить» у администратора показывается лишь для статуса «Новая».
- «Портфолио» и кнопка «Позвонить» отложены (см. README).

## Готовность к MAX Mini App

Слой `lib/booking` не знает про транспорт. Для Mini App достаточно добавить `app/api/miniapp/*` (список услуг/мастеров, `getAvailableDates`, `getSlotsForMasters`, `createBooking`,
`cancelBooking`), проверяя подпись данных запуска Mini App по официальной документации MAX, и привязывая клиента к `User.maxUserId`. Переписывать backend не нужно.
