# Безопасность

## Что сделано

| Область | Меры |
|---|---|
| Секреты | только переменные окружения; `.gitignore` для `.env*` и ключей; нет `NEXT_PUBLIC_` для секретов; логи вырезают поля `token/secret/password/key/authorization/cookie`, телефоны маскируются |
| Webhook MAX | HTTPS; заголовок `X-Max-Bot-Api-Secret` (сравнение за постоянное время); лимит тела 256 КБ; идемпотентность; токен MAX только в заголовке `Authorization` |
| Cron | `Authorization: Bearer $CRON_SECRET`, иначе `401` |
| Админ-панель | bcrypt (12), длина пароля ≥12, лимиты по IP/email, блокировка после 5 ошибок, выравнивание времени ответа, сессия 8 ч в `HttpOnly; Secure; SameSite=Strict` cookie, `tokenVersion` для мгновенного отзыва |
| Авторизация | роль и активность из БД на каждый запрос; право проверяется в каждом серверном действии; CSRF-токен в каждой форме (плюс проверка Origin у server actions); мастер видит только свои записи |
| Ввод | серверная валидация имён, телефонов, id, дат, времени, callback; параметры URL приводятся к безопасным; редиректы только на разрешённые пути |
| SQL / XSS | Prisma (параметризованные запросы; сырой SQL только с параметрами); React экранирует вывод; значения в Google Таблицу пишутся как `RAW` (нет формул) |
| AI | в OpenAI только каталог и обезличенный текст; ответ проверяется кодом (id услуг по БД, запрет цен/времени/«записал» вне каталога); лимиты на пользователя и в сутки |
| Заголовки | `nosniff`, `X-Frame-Options`, HSTS, `Referrer-Policy`, для `/admin` — `no-store`, `noindex`, `frame-ancestors 'none'` |
| Защита от спама | 15 событий / 10 с на пользователя (счётчик в БД) |
| ПДн | уведомление о согласии, удаление данных по запросу (обезличивание, включая таблицу), RBAC, журнал действий |

## Ограничения и что сделать дополнительно

- Нет двухфакторной аутентификации панели — используйте длинные уникальные пароли и включите защиту деплоя на Vercel для Preview.
- IP берётся из `x-forwarded-for` (на Vercel его выставляет платформа). За другим прокси настройте доверие иначе.
- Блокировка по email позволяет постороннему временно закрыть администратору вход (цена защиты от подбора); владелец может сбросить блокировку сменой пароля.
- Полный CSP со скриптами не включён (Next.js использует inline-скрипты); задан безопасный минимум.
- Данные хранятся у зарубежных провайдеров — см. раздел 152-ФЗ в README.
- Регулярно: `npm audit`, обновление зависимостей, ротация токенов/ключей при смене сотрудников, проверка журнала.
