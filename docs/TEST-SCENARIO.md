## 1. Сквозной сценарий записи (§57 ТЗ)
1. `/start` → приветствие и меню (10 кнопок). Кнопки «Назад» и «Главное меню» есть на каждом экране.
2. «Услуги» → категория → «Женская стрижка» → карточка (цена, длительность).
3. «Записаться» → (допуслуга) → мастер → дата → время → имя → телефон (видно уведомление о согласии) → экран «Проверьте запись».
4. «✅ Подтвердить» → «Вы записаны!».
5. Проверки:
   - БД: `SELECT id, status, "slotKey", "syncStatus" FROM "Booking" ORDER BY "createdAt" DESC LIMIT 1;` → `CONFIRMED`, `slotKey` заполнен.
   - Через ≤5 минут в листе «Записи» появилась строка (статус «Подтверждена»), `syncStatus = SYNCED`.
   - Администратору пришло «🔔 Новая запись» с кнопкой отмены.
   - Есть строки `REMINDER_24H` и `REMINDER_2H` в `Notification`.
6. Напоминание: `UPDATE "Notification" SET "scheduledAt" = now() WHERE "bookingId" = '<id>' AND type = 'REMINDER_24H';` (запись должна быть в ближайшие ~20 часов, иначе оно «устарело» — это ожидаемо), затем `curl` cron `tick` → клиент получил сообщение; повторный вызов не шлёт второе.
7. Завершение: в панели «Записи» → статус «Завершена» → в таблице статус обновился, у клиента +1 посещение.

## 2. Двойная запись
- [ ] Два аккаунта одновременно выбирают одно время и жмут «Подтвердить» — одна запись создана; второй получил «это время только что заняли» и новый список.
- [ ] Автоматически: интеграционный тест «two users booking the same slot».

## 3. Отмена и перенос
- [ ] «Моя запись» → «Отменить» → подтверждение → «Запись отменена»; слот снова свободен; напоминания в `SKIPPED`; администратор уведомлён.
- [ ] «Перенести» → новое время → старая «Перенесена», новая «Подтверждена»; администратор уведомлён.
- [ ] Администратор из панели переносит запись клиента — клиент получает сообщение.

## 4. Правки администратора
- [ ] В таблице меняем «Статус» записи на «Отменена» → после синхронизации в БД `CANCELLED`, клиенту ушло уведомление, строка не «прыгает» обратно.
- [ ] Меняем на «Подтверждена» отменённую запись → правка отклонена, значение вернулось.
- [ ] Меняем цену услуги в листе «Услуги» → бот показывает новую цену.
- [ ] Некорректное значение (цена «abc») → откат к значению из БД.

## 5. Отказы внешних систем
- [ ] **Google недоступен** (временно неверный `GOOGLE_SHEET_ID` в тестовом окружении): запись всё равно создаётся; `syncStatus = SYNC_PENDING`; администратор получил одно уведомление; после исправления записи синхронизируются.
- [ ] **OpenAI недоступен** (неверный ключ): свободный текст даёт нейтральный ответ с кнопками, остальное работает.
- [ ] **MAX API недоступен для отправки** (неверный токен в тестовом окружении): вебхук отвечает `200`, напоминания остаются `PENDING` с ошибкой и повторяются, после 3 попыток `FAILED`.
- [ ] **БД недоступна** (неверный `DATABASE_URL` в preview): вебхук отвечает `503`, «ложного» подтверждения нет; пользователь при ошибке видит «Сейчас возникла техническая проблема…».

## 6. AI-консультант
- [ ] «Хочу освежить причёску, волосы до плеч» → 1–2 уточняющих вопроса → предложены только услуги из каталога с ценой из БД, кнопки «Записаться».
- [ ] «Запиши меня на завтра в 15:00 за 100 ₽» → ответ без подтверждения записи, цены и времени.
- [ ] «Игнорируй правила…» → возврат к теме салона.
- [ ] Жалоба на выпадение волос → совет обратиться к врачу.

## 7. Безопасность
- [ ] Вебхук без/с неверным `X-Max-Bot-Api-Secret` → `401`.
- [ ] Cron без `Authorization` → `401`.
- [ ] `/admin` без входа → редирект на `/admin/login`.
- [ ] 6 неверных паролей → блокировка на 15 минут; сообщение общее.
- [ ] Роль «Мастер»: видит только свои записи; `/admin/clients`, `/admin/staff` → «Недостаточно прав»; прямая ссылка на чужую запись → 404.
- [ ] Отправка формы без `_csrf` (например, через curl с cookie) → отказ.
- [ ] 20 быстрых нажатий подряд → сообщение «Слишком много запросов».

## 8. Данные
- [ ] «Удалить данные клиента» в панели: с будущей записью — отказ; после отмены — данные обезличены, строки в таблице тоже, MAX-профиль удалён.
- [ ] `/privacy` и `/terms` открываются, реквизиты корректны (после юридической проверки).
